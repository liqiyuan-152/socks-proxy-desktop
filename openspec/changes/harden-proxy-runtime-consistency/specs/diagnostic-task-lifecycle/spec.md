## Purpose

为代理延迟测试和规则预测建立跨页面有效的任务边界，使并发资源使用、取消行为及结果有效性由后端与前端共同保证，避免重复测试、已过期结果和后台遗留进程误导用户。

## ADDED Requirements

### Requirement: 后端测速资源限制与去重

系统 MUST 在整个应用范围内将同时执行的延迟测试限制为最多 3 个，并对同一档案及同一配置版本的重复请求复用任务。等待队列 MUST 有限且超限时返回明确繁忙状态；仅依赖某一页面的按钮禁用或批量限制不得视为满足要求。

#### Scenario: 单测与批测交错

- **WHEN** 用户通过多个入口请求超过 3 个不同代理的延迟测试
- **THEN** 后端同时运行的测试不超过 3 个，其余进入有界队列或返回繁忙状态

#### Scenario: 同一代理重复提交

- **WHEN** 多个调用者请求同一代理同一修订的测速
- **THEN** 系统复用同一实际测试并为各调用者返回对应任务状态

### Requirement: 测速取消与修订隔离

系统 SHALL 为任务提供稳定标识和取消操作；最后一个订阅者离开、主动取消或任务输入修订失效时 MUST 移除尚未运行的任务并终止不再需要的运行任务。取消完成前 MUST 回收测试拥有的进程与临时配置，且不影响主代理内核；被取消或过期的结果不得作为当前测量展示。

#### Scenario: 页面离开后重新进入

- **WHEN** 页面离开导致测速订阅结束，并在随后重新进入页面发起测试
- **THEN** 旧任务取消或被显式复用，不突破全局并发限制，也不向新页面写入旧修订结果

#### Scenario: 凭据在测速期间更新

- **WHEN** 某档案的凭据版本在测速过程中变化
- **THEN** 旧修订测试失效，新请求使用一致的新档案和凭据快照

### Requirement: 路由预测绑定输入和已保存配置

规则测试结果 SHALL 标明实际测试的目标、端口和配置版本，并保持仅预测已保存规则模式出口的语义。输入、规则、默认出口或预设变化时 MUST 清除结果或明确标记过期；迟到请求不得覆盖较新请求。

#### Scenario: 等待结果期间编辑目标

- **WHEN** 用户发起目标 A 的预测后把输入改成目标 B
- **THEN** A 的返回结果不会被展示成 B 的当前预测

#### Scenario: 修改已保存规则

- **WHEN** 用户成功修改规则、默认出口或国内直连预设
- **THEN** 旧配置版本的预测被清除或标记过期，重新测试使用新版本

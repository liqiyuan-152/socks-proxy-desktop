### Existing Specification Alignment

主规格目录当前为空。两个历史变更已勾选全部任务，但未归档；本次不改动其完成记录，也不自动归档。

- 保留 `multi-proxy-routing` 的默认代理引用约束、规则优先级和不静默降级语义。
- 早期 `proxy-configuration` 描述删除活动档案时自动停止/切换，后续多出口规格要求拒绝删除被默认出口或规则引用的档案。本次沿用较新的拒绝行为，不重新引入自动删除。
- 历史多出口提案写明一个内核加载所有启用出口。本次将全局模式收窄为默认出口，规则模式仍加载所有启用出口；这是明确的内部资源及无关凭据失败隔离调整，不改变实际路由选择。
- 历史原子提交要求覆盖可返回错误的回滚；本次新增中断后恢复保证，普通 SQLite 事务本身不能覆盖系统凭据存储与注册表。
- 历史“内核启动失败清除本次运行时长”适用于未成功建立的新会话；保留下来的旧会话保留其时长和已应用模式。
- 归档本变更前需复核历史规格同步顺序与上述差异；本次新增规格使用独立名称避免伪造不存在的 MODIFIED 基线。

## Goals / Non-Goals

**Goals:**

- 以实际生效的运行计划和会话身份为一致性边界，凭据、操作结果、配置版本均可追踪。
- 控制请求与临时任务有明确资源上限，故障不阻塞主会话管理。
- 每个高优先级问题有跨模块验收场景，验证记录关联提交和环境。

**Non-Goals:**

- 不替换 Tauri、React、SQLite 或 sing-box，不引入通用工作流引擎。
- 不扩展非 Windows 代理支持，不实现 TUN、自动选择出口、故障切换或完成连接历史。
- 不在本变更接入签名、自动更新或公开 Release；只验收现有内测产物。
- 不按行数机械拆分无关代码，不增加密码摘要缓存或取消内核完整性校验。

## Decisions

### 1. 先恢复干净检出验证

添加 `.gitattributes` 为文本明确 LF，二进制资源按二进制处理；仅规范化确受影响文本。保持格式检查，避免在 CI 临时跳过检查或自动改写源码掩盖差异。Windows 流水线分别标识单元、真实内核和构建阶段；真实内核阶段启动前检查文件、版本和哈希，缺失时明确失败。

不重跑与文档整理无关的应用测试；实施时按受影响范围验证，并以 Windows 干净检出作为 CI 修复的验收点。

### 2. 用运行计划表达真实变更

新增纯计算的 `RuntimePlan`，包含当前模式、实际出站参数、规范化规则及每个出口的不透明凭据版本。展示名称和无关设置不参与进程切换判断；规则名称映射随配置提交更新。全局模式只选默认出口，规则模式保留所有启用出口；直连不建立内核计划。

配置修订表示成功持久化的配置，运行计划修订表示实际运行输入，凭据版本由独立标识产生。先用明确的凭据变更集合修复漏应用，再收敛为统一计划；不得仅增加前端版本或用秘密哈希代替运行时输入。

组合测试使用真实 `ConfigurationService + ManagedRuntime` 和可观察启动参数的假内核，验证仅替换用户名/密码及同配置导入确实触发运行计划变更。旧凭据与旧进程须保留到候选数据库提交成功。

### 3. 将会话健康与操作结果分开

快照提供会话健康和最近操作结果；期望模式、已应用模式保持各自语义。近期失败附带脱敏原因及操作标识，不将仍健康的旧会话变成无人看护的状态。协调器只要持有已提交活动会话且不处于受串行操作保护的切换窗口，就执行存活核对。

前端、侧栏及托盘统一读取该快照；状态页显示失败原因与仍生效的模式。IPC 失败但快照读取成功时保留原操作错误。恢复失败时显示“恢复未完成”，不将缺失会话简单等同为系统代理已恢复。

保留单写者串行提交，暂不引入完整 actor 框架；模块可分为会话转换、看护和配置提交，以保持职责清晰。

### 4. 抽取独立控制客户端

使用已有 reqwest 封装同步调用边界的 `CoreControlClient`，显式 `no_proxy`、禁止重定向，设置连接超时及 2 秒总截止时间，支持标准 HTTP 分帧。实施中的持续慢响应测试证明阻塞响应读取无法可靠执行总截止时间，因此内部采用异步响应流和 Tokio 总时限，外部保留同步调用。逐块累计最多 1 MiB，下一块超过剩余额度即拒绝，不截断成成功结果；错误只输出受控类别。

在会话锁内获取不可变控制端点、密钥及 `run_id`，释放锁后请求，返回后核对当前 `run_id`；切换后的迟到结果丢弃。密钥只保留在内部客户端，不进入 DTO、Debug 输出或诊断。保留现有回环绑定、随机密钥和资源校验。

相较继续扩展手写 HTTP，此方案复用现有依赖并覆盖分块及截止时间。慢请求最多占用工作线程到总截止时间，不持有进程管理锁。

### 5. 数据库迁移与跨资源恢复分层实施

先将每一迁移步的 DDL 和 `user_version` 写入显式事务，补充中断注入测试。

随后采用版本化凭据引用：新秘密写入新的系统凭据条目，旧条目保留；普通恢复日志仅记录事务 ID、旧/新引用、旧/新配置修订、启动项原值/预期值及阶段，不记录密码。凭据读取统一使用内部引用，逐步迁移当前默认以档案 ID 读取的路径。

提交过程为：持久化恢复意图 → 暂存新凭据 → 应用启动项和候选运行计划 → 在同一个 SQLite 事务中保存新配置、引用及提交标记 → 确认内核 → 清理旧凭据与恢复记录。配置未提交时恢复旧状态；已提交时完成新状态清理。删除凭据同样延后到提交后清理。

启动时取得现有单实例锁，先处理系统代理遗留记录，再处理配置事务恢复，完成前不接受配置写入或代理接管。恢复动作可重复执行。启动项适配器记录并比较实际条目值，而非只比较启用布尔值；无法确认归属时保留现场。不得把旧密码写入 SQLite 来简化回滚。

替代方案是仅持有内存旧值并依赖异常处理，该方案保留现有断电窗口；普通数据库事务也无法包住凭据存储，故不采用。

### 6. 后端拥有诊断任务生命周期

新增应用级测速注册表，执行并发上限 3、等待队列上限 32，队列满返回繁忙。任务键包含档案 ID 和用于测试的配置/凭据版本；同键复用任务，各页面以订阅标识持有结果。最后一个订阅者取消时移除排队任务，运行任务接收取消信号并终止所属测试内核，完成回收后才报告已取消。

配置服务在串行边界内提供一致的测试输入快照，任务运行不持有配置写锁。异步请求与取消信号协作，控制/启动等待点检查取消；不依赖停止 await 一个阻塞任务来终止子进程。沿用现有受管进程隔离、Job 和私有临时配置机制。

路由预测返回请求目标、端口和配置修订。前端输入变更立即失效，配置成功提交事件同步使结果过期，并以请求序号丢弃迟到结果。此处不以运行时 revision 代替配置版本，因为未运行时也可修改配置。

### 7. 类型契约和页面拆分随行为变更推进

在 `src/lib/` 建立按命令名关联参数和结果的类型化 API；Rust 可序列化 DTO 作为契约来源，实施时引入类型导出工具并检查生成结果是否漂移。只有公开非敏感 DTO 参与导出，凭据命令输入输出保持明确受控边界；生成类型不替代导入 JSON 的后端校验。

代理页提取编辑/凭据生命周期，规则页提取读取与写入逻辑，列表渲染与领域数据转换分离。统一处理请求世代、重复提交和错误呈现；复用现有 shadcn 基础组件。避免为了消除重复而抽象一个覆盖所有页面的通用表单框架。

## Risks / Trade-offs

- [运行计划比较遗漏实际输入] → 规范化计划覆盖模式、路由顺序、出站参数和凭据版本，并以修改每类输入的组合测试验证。
- [增加快照字段导致多个显示入口不一致] → 同步更新前端、托盘、IPC 测试和生成契约，保持已应用模式的唯一来源。
- [版本化凭据升级后旧二进制不理解新格式] → 升级前备份数据库；升级后禁止直接运行旧版本写入，回退通过匹配数据库备份与凭据恢复流程完成。
- [取消只停止等待而遗留进程] → 以进程退出和临时配置删除作为取消完成条件，并检查主代理进程不受影响。
- [控制请求上限影响极大量连接观测] → 明确显示超限降级；先保持 1 MiB 上限，后续按测量单独调整，不伪造部分计数。
- [跨资源恢复本身失败] → 持久化阶段不提前清除；恢复可重试且显示明确待处理状态，避免覆盖第三方启动项或代理设置。
- [本地平台测试通过但 Windows 不可用] → 单独保留目标平台与桌面验收状态，不以单元测试数量代表真实内核或安装包验收。

## Migration Plan

1. 恢复 Windows CI，明确真实内核验证阶段，建立可依赖基线。
2. 添加能失败的组合测试，修复凭据应用和旧会话看护；同步错误展示。
3. 抽出控制客户端并修复迁移事务，运行慢响应、协议及迁移故障测试。
4. 引入运行计划、凭据引用升级和恢复日志，完成各提交边界的崩溃注入测试后才启用升级。
5. 引入后端诊断任务管理、版本化路由预测和类型化页面 API，保持前后端同一版本发布。
6. 完成完整检查、Windows 固定内核测试和现有 NSIS 安装包桌面验收，记录提交、环境、结果及限制。

前 3 步可分提交交付；涉及数据库升级的步骤在可恢复测试通过前不交付给用户。回退时停止应用、恢复升级前数据库及对应凭据状态，禁止只替换旧可执行文件。导出文件始终不含密码，不能作为凭据回退备份。

## Open Questions

- Windows 真实内核通常返回何种活跃连接分帧，以及高连接数响应大小分布，需在目标平台采样；不影响支持标准分帧及有界读取的决定。
- 类型导出工具的具体版本需按当前 Rust/Tauri 依赖和 MSRV 兼容性确定；命令映射、生成漂移检查及非敏感 DTO 边界保持不变。
- 真实桌面验收使用的 Windows/WebView2 版本在执行时记录；未获得环境时相应任务保持未完成。

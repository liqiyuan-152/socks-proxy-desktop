## Why

基于提交 `1a073c3` 的审查发现，凭据单独更新、切换失败后的旧会话看护、控制接口解析及数据库迁移存在一致性缺口；最新 Windows Quality 流水线又在格式检查阶段失败，未提供目标平台验证结果。需要先恢复验证链，再把配置、凭据、实际运行会话和用户可见反馈统一起来。

## What Changes

- P1：约束 Git 文本换行符，修复 Windows 干净检出的格式检查，恢复真实内核测试与构建验证。
- P1：将凭据变更纳入运行时提交；即使非敏感配置相同，运行中的受影响出口也必须使用新凭据，失败时恢复旧状态。
- P1：拆分当前会话状态与最近操作结果，切换失败后继续看护保留的旧内核，并在其退出时执行已有所有权恢复流程。
- P2：封装内核 HTTP 控制客户端，支持标准响应分帧、总超时和大小上限，避免网络读取长时间占用会话锁。
- P2：统一展示脱敏运行时错误、操作结果和恢复入口；路由预测结果绑定测试输入与配置版本。
- P2：将数据库结构变更与版本更新放入同一事务；将凭据、开机启动等跨资源提交扩展为可在崩溃后恢复的流程。
- 后续重构：引入按模式生成的运行计划，减少不影响实际路由的内核重启；在后端统一限制、去重和取消测速任务；建立类型化 IPC 契约并按职责拆分页面。
- 补充跨层故障测试和 Windows 桌面验收。实施进度以 `tasks.md` 为准，已执行检查与证据边界见 `verification.md`；规划文档完成不代表代码或目标平台验收完成。

## Capabilities

### New Capabilities

- `runtime-consistency`: 凭据生效、按模式运行计划、失败后会话看护与一致提交。
- `core-control-observation`: 有界 HTTP 控制请求、会话隔离及可解释错误反馈。
- `configuration-recovery`: 原子迁移、跨资源提交恢复及敏感数据隔离。
- `diagnostic-task-lifecycle`: 后端测速并发与取消、路由预测结果有效性。
- `desktop-quality-gates`: Windows 干净检出、显式真实内核测试和桌面验收证据。

### Modified Capabilities

无。`openspec/specs/` 当前没有主规格；已有行为仅记录于两个已完成但未归档的变更。本提案增加聚焦的加固规格，不把这些历史增量误作主规格进行 MODIFIED 操作。与历史规格的衔接及冲突在 `design.md` 记录。

## Impact

- Rust：配置服务、凭据存储、运行时协调器、sing-box 配置和进程管理、SQLite 迁移、诊断、测速、IPC 与托盘。
- 前端：后端状态与命令契约、模式错误反馈、代理编辑、规则管理、测速和规则测试结果展示。
- 工程：`.gitattributes`、Windows Quality/内测打包工作流、组合测试、安装包验收记录。
- 数据与兼容性：保留现有导入/导出 v1/v2 兼容语义与无密码导出；内部凭据引用和恢复记录可能需要数据库升级。运行时/任务 DTO 按前后端同版本同步演进，不提供新旧二进制混用承诺。
- 不改变 Windows x64、用户级系统代理的产品边界，不新增 TUN、自动选路、完成连接历史、签名发布或自动更新。

## 2. P1 — 凭据应用与旧会话看护

- [x] 2.1 建立真实配置服务与运行时协调器组合测试夹具，让假内核记录实际配置和凭据版本；验证仅改密码、仅改用户名、相同配置重新导入能复现当前漏应用问题。
- [x] 2.2 将受影响凭据变更显式传入候选运行时提交，避免相同非敏感配置短路；验证 2.1 场景通过，候选启动或存储失败仍恢复旧凭据与旧会话。
- [x] 2.3 在运行时快照中分开会话健康与最近操作结果，保留已应用模式；验证切换失败仍检查旧会话，旧会话随后退出时执行系统代理恢复。
- [x] 2.4 同步前端状态页、侧栏和托盘，显示脱敏失败原因、仍生效模式及适用恢复操作；用 Vitest 和托盘状态测试验证操作失败后快照读取成功不会吞掉错误。

## 3. P2 — 控制接口与数据库迁移

- [x] 3.1 抽取基于现有 HTTP 依赖的控制客户端，禁用代理和重定向，实施 2 秒总时限及 1 MiB 解码响应限制；用分块、慢速、超限、401 和无效 JSON 服务夹具验证。
- [x] 3.2 将控制请求移出会话管理锁，并核对返回结果所属运行 ID；通过慢响应与同时切换/停止测试验证无锁等待耦合、旧结果不覆盖新会话。
- [x] 3.3 将每步数据库 DDL 与版本更新放进同一事务；注入建表后中断并重新打开数据库，验证可重试、原配置保留以及拒绝更高版本。

## 4. 运行计划与无关变更隔离

- [x] 4.1 提取纯运行计划构建模块，区分配置修订、运行计划修订和不透明凭据版本；逐字段测试验证名称/无关设置不触发内核切换，出口参数和凭据变化触发切换。
- [x] 4.2 让全局计划仅加载默认出口，规则计划保留所有启用出口和既有优先级；验证无关出口缺少凭据不阻断全局模式，多出口规则和国内直连行为无回归。
- [x] 4.3 将配置服务、内核渲染和运行时比较接到统一计划，并移除临时重复判断；以组合测试验证提交失败恢复旧计划，重命名保持进程身份且展示更新。

## 5. 配置跨资源崩溃恢复

- [x] 5.1 增加版本化内部凭据引用及升级逻辑，统一配置服务、主内核与测速的凭据读取；验证旧档案升级可重试、v1/v2 导入行为不变且导出无内部引用或秘密。
- [x] 5.2 增加非敏感事务恢复记录，并把配置、引用及提交标记放在同一 SQLite 事务；序列化检查确保恢复记录、事件和诊断均不含密码或可逆凭据。

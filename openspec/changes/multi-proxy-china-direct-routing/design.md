## Context

参见 proposal.md。当前 `PersistedConfiguration` 版本为 1，保存 `active_profile_id` 和只有代理/直连两种动作的有序规则；`sing_box_config::render` 只生成 `selected-proxy`、`direct` 两个出站。`SingBoxRuntimeBackend` 仅加载活动档案的凭据，`SingBoxProcess` 以单个临时配置启动内核，Windows 只接管遵循用户级系统代理的应用。现有变更 `implement-proxy-runtime-backend` 已完成但规格尚未同步到主规格；这里保留其候选修订、失败回滚、凭据隔离及未命中直连的约束。

## Goals / Non-Goals

**Goals:**
- 单入口、多出站、稳定档案 ID 引用和可解释的优先级；运行时提交失败恢复旧版本。
- 旧持久化配置及旧导入文件可迁移，关闭预设时的流量决策不变。
- 国内直连预设可离线运行，并有可验证的域名、字面 IPv4/IPv6 与规则集行为。

**Non-Goals:**
- 自动选择最优出口、负载均衡、故障时自动切出口、TUN、全设备 DNS 接管、GFW 可达性探测。
- 为每个代理启动独立内核或分别写入多个 Windows 系统代理设置。

## Decisions

### 1. 稳定引用与模式

配置升为版本 2；保留 `active_profile_id` 的兼容读入，但新格式使用 `default_profile_id`。规则保持 `action` 为 `proxy`/`direct`，增加 `proxy_profile_id`：代理动作必须引用已启用档案，直连动作不得携带出口。内存中的旧版迁移在解析阶段将旧代理规则绑定原活动 ID，旧版没有活动档案时保留可编辑的未解析引用并阻止规则代理启动，不能悄悄转为直连；保存修复后的新配置才要求完整引用。导入先迁移并验证所有规则与凭据，再一次性提交；导出仅输出 v2，不含凭据。

`default_profile_id` 是全局模式唯一出口，也是国内直连预设的未命中出口；普通规则模式关闭预设时仍以 `direct` 结束。启用档案只表示可作为出口，规则及默认出口引用停用或不存在档案时拒绝更改；未引用的档案可删除。保留现有“选择活动档案”的 UI 操作但将其改名并接到默认代理。相比新增“代理组”，这个模型延续稳定 ID 和单内核事务边界。

### 2. 单内核多出口与凭据

按稳定 ID 派生不会与 `direct` 等保留 tag 冲突的出站 tag；渲染所有启用代理，规则按原顺序映射到对应 tag，明确指定 `route.final`。后端为所有启用的、参与当前运行时的代理读取独立凭据，在生成临时配置前验证缺失凭据；密码仅存在受限临时文件中，不进入 DTO、事件和导出。切换时继续先启动候选进程、健康检查、切系统代理，再提交配置；任一环节失败继续使用已应用版本。相比在 Rust 中实现转发，此方案复用锁定 sing-box 内核。

### 3. 国内直连预设与规则集

增加独立布尔设置，默认关闭。启用时先输出用户规则，再输出中国域名集直连，以及仅针对入口目标为字面 IP 的私有/局域网地址和中国 IPv4/IPv6 地址集直连，最终出站是默认代理；全局模式不生成这些规则。不得对未命中域名集的域名执行 IP 集预设匹配，即使内核拥有解析后的候选地址。优先级允许用户对国内地址显式代理，也允许对海外目标直连。预设不读取旧版 `geoip`/`geosite` 字段，而采用所锁定 sing-box 版本支持的本地规则集格式。将来源、生成提交、许可证、SHA-256、数据日期和产物纳入发布清单，打包离线资源并在启用前校验；此阶段不做运行时远程自动更新。规则集有损坏或缺失时拒绝候选修订，不以空集合继续。

应用配置生成前须以实际打包版本的 `sing-box check` 和集成连接测试证明：域名集和字面 IPv4/IPv6 IP 集可以被加载、规则顺序与出口正确。数据归属会变动，但不等于网站可达性；界面只称“国内直连”，明确域名集外的域名仍走默认代理。相比在线下载，随版本打包减少离线启动失败和运行时数据漂移。

### 4. 域名边界和自测

先按用户规则匹配，随后仅对域名使用中国域名集，对字面 IP 使用私有/局域网及中国 IPv4/IPv6 地址集。域名集外的域名直接选默认代理，不能因为 DNS 的任一候选 A/AAAA 属于中国地址集而改为直连；重试或地址族回退不改变该域名的出口。字面 IP 可确定归属，其余未命中 IP 走默认代理。代理上游地址和内核内部连接不能递归送回本地入口；域名解析失败只会导致代理连接失败或维持默认代理选择，不能转为直连。系统代理未接管的应用 DNS 请求不在保障范围。

规则测试由后端以当前候选/已提交修订的规则数据解释首条命中、预设阶段和出口；域名集外的域名无需 DNS 判断即可报告默认代理出口，字面 IP 按打包数据版本判断。测试单独只读，不更改系统代理或运行模式，不把出口预测冒充连接成功或最终拨号 IP；规则集不可用或目标无效时报错而不伪造命中。相比前端重写一套规则引擎，这样可降低解释与真实路由偏差；仍需以固定版本集成用例验证。

## Risks / Trade-offs

- [现有 v1 无活动档案但有代理规则] → 迁移保留未解析引用和可编辑配置，阻止代理模式直到修复；不得在读库时丢弃规则。
- [域名集不包含某个解析至中国 IP 的域名] → 仍走默认代理；界面明确这是保守覆盖范围，不声称识别所有国内站点。固定内核版本经真实受管入口测试混合 A/AAAA、重试回退及解析失败均不因 IP 集误直连。
- [代理服务器地址恰好属于中国 IP] → 上游拨号不通过本地入口再次匹配；启动/切换测试检查循环与凭据隔离。
- [规则集体积、时效及版权] → 发布清单固定来源、许可证、日期及校验值；不把离线旧数据说成实时准确。
- [部分代理不可用] → 不降级直连；规则解释指出选中的出口，不从仅含活跃连接的快照推断失败结果；候选配置回滚与既有系统代理所有权机制保持一致。

## Migration Plan

1. 先增加对本地 v1 和导入 v1 的显式迁移及往返测试，保留备份与旧规则顺序；空活动档案的代理规则保持待修复状态。
2. 再引入 v2 校验、多个凭据/出站、UI 与规则测试；预设默认为关闭，使旧用户无需改变操作即可维持原路由。
3. 完成规则集来源与固定版本验证后开放预设；失败不修改已提交设置。回滚应用版本前保留 v1 备份，旧应用不能直接读取 v2，需使用受控转换或恢复备份。

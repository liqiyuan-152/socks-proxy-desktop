## Why

当前规则只能将流量送往唯一活动代理，无法让不同站点使用不同代理。用户也无法启用可解释的国内直连策略，同时保持已有规则配置的路由语义。需要在现有系统代理覆盖范围内扩展多出口路由，并将国内直连做成明确可选的预设。

## What Changes

- 一个受管内核同时加载多个已启用代理出口；规则可选择指定代理或直连，全局代理使用明确的默认代理。首期不加入自动测速、故障切换、负载均衡或多内核实例。
- 为规则模式增加可选“国内直连”预设：用户规则优先，命中中国域名集的域名以及私有/局域网或中国 IPv4/IPv6 集中的字面 IP 直连；其他域名和 IP 走默认代理。关闭预设时保留原有未命中直连语义。
- 明确预设不对任意域名解析得到的 IP 作直连判断；定义规则集来源、离线与故障行为，提供规则命中测试及出口解释，避免将 IP 地理归属误称为 GFW 可达性判断。
- **BREAKING（配置格式）**：新增规则出口引用、默认代理及预设设置，需要配置版本迁移及导入兼容；已有“代理”规则迁移为引用原活动代理，旧规则未命中行为不得改变。
- 删除或停用被引用的代理时拒绝操作并提供可定位错误；代理不可用不得静默改为直连。保留原有 Windows 用户级系统代理覆盖范围及直连恢复机制。

## Capabilities

### New Capabilities

- `multi-proxy-routing`: 多出口规则选择、默认代理、配置迁移和引用完整性。
- `china-direct-routing`: 可选国内直连预设、字面 IP 与域名规则集边界、离线数据生命周期、命中解释和故障处理。

### Modified Capabilities

- 无。现有代理配置与运行时规格尚位于已完成变更的增量规格中，未同步到 `openspec/specs/`；新规格显式描述其扩展及兼容条件。

## Impact

- Rust：`models`、`store`、`transfer`、`configuration_service`、`credentials`、`sing_box_config`、`sing_box_process`、`runtime`/`runtime_manager`、观测与 IPC；新增规则集资源与字面 IP/域名路由边界验证。
- 前端：代理列表中的默认代理、规则出口选择与端口范围、国内直连预设及规则测试；更新对应 DTO、状态和测试。
- 发布：锁定 sing-box 版本的配置验证，规则集数据的可信来源、版本和更新/离线行为须明确；不承诺 TUN、全设备接管或 GFW 检测。

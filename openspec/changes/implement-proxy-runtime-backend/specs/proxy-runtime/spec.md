## Purpose

为桌面应用提供受控的代理内核运行时和 Windows 系统代理适配，使三种代理模式与真实的进程状态、已应用配置和可恢复的系统网络设置一致。

## ADDED Requirements

### Requirement: 真实运行时快照

系统 SHALL 向前端提供包含期望模式、已应用模式、阶段、活动代理、运行时长、系统代理状态、TUN 状态和最后错误摘要的运行时快照。系统 MUST 仅在内核成功就绪后报告已应用代理模式和运行时长。

#### Scenario: 内核成功就绪

- **WHEN** 所选档案的内核已启动、健康检查通过且系统代理设置完成
- **THEN** 快照将阶段报告为运行中、已应用模式报告为请求模式，并从就绪时刻开始计算运行时长

#### Scenario: 内核启动失败

- **WHEN** 内核无法启动或健康检查失败
- **THEN** 快照报告失败原因，不将请求模式报告为已应用模式，并清除本次运行时长

#### Scenario: 多个界面读取状态

- **WHEN** 状态页、侧栏、底部状态栏或托盘读取运行时状态
- **THEN** 它们获得同一快照修订所描述的已应用模式、活动档案和阶段，而不显示各自维护的示例成功状态

### Requirement: 原子模式切换与回滚

系统 SHALL 串行执行规则代理、全局代理和全局直连之间的切换。切换期间 MUST 报告进行中阶段；只有新配置完全就绪后才能提交新的已应用模式。失败时 MUST 恢复上一个可运行状态，或明确报告无可恢复运行时。

#### Scenario: 成功热切换代理模式

- **WHEN** 正在运行的内核收到有效的规则代理与全局代理互切请求
- **THEN** 系统在提交前保持原已应用模式，并在新配置就绪后更新已应用模式且保留同一运行时长

#### Scenario: 切换失败回滚

- **WHEN** 新模式的配置加载、内核重载或系统代理更新失败
- **THEN** 系统恢复先前已应用模式及其系统代理状态，并在快照中报告本次失败

### Requirement: 首期模式覆盖范围

首期规则代理和全局代理 MUST 仅声明为覆盖遵循 Windows 用户级系统代理设置的应用流量；不遵循该设置的应用流量不属于首期接管范围。运行时快照 SHALL 报告系统代理覆盖范围，前端不得将此状态描述为所有网络流量均已代理。全局直连 MUST 恢复系统代理设置。

#### Scenario: 启用全局代理

- **WHEN** 用户成功切换到全局代理
- **THEN** 快照报告全局代理已应用且覆盖范围为系统代理应用，并保留未启用 TUN 的事实

#### Scenario: 显示覆盖范围

- **WHEN** 状态页呈现规则代理或全局代理的运行时快照
- **THEN** 页面显示系统代理覆盖范围提示，不将未受系统代理控制的流量标记为已代理

### Requirement: Windows 系统代理所有权与恢复

在 Windows 上，系统 SHALL 仅在本应用内核已就绪时启用本应用管理的系统代理设置，并在写入前持久化启动前设置、待写入预期设置和所有权令牌，写入成功后标记已提交。当前完整设置等于已提交或待写入的预期设置时，系统才可在切换直连、停止、启动失败、异常退出恢复、正常退出或手动网络恢复时恢复启动前保存的设置；待写入状态下当前完整设置仍等于原值时可清理待写记录。当前设置既不等于原值也不等于已记录的预期值时，系统 MUST 保留现场与恢复记录，报告需人工检查并阻止新的系统代理接管，不得按字段猜测归属或修改无法确认归属的第三方设置。

#### Scenario: 切换到全局直连

- **WHEN** 用户请求全局直连且当前由本应用管理系统代理
- **THEN** 系统恢复启动前的系统代理设置并在快照中报告全局直连已应用

#### Scenario: 检测异常遗留状态

- **WHEN** 应用启动时发现上一次运行留下的本应用管理标记
- **THEN** 系统先尝试恢复保存的系统代理设置，再接受新的模式切换请求

#### Scenario: 系统代理在运行期间被外部修改

- **WHEN** 应用停止或恢复时发现当前系统代理设置不等于本应用写入后的预期设置
- **THEN** 系统不恢复启动前设置；若不能确认当前设置是否由本应用部分写入，保留恢复记录并报告需人工检查，不覆盖当前设置

#### Scenario: 代理设置逐字段写入中断

- **WHEN** 写入中断后，下次启动或用户手动恢复时当前完整设置既不等于保存的原值，也不等于待写入的预期值
- **THEN** 系统不自动恢复、不清除恢复记录、不接受新的系统代理接管，并返回可显示的人工检查提示

### Requirement: 单实例运行时所有权

系统 MUST 在每个 Windows 用户会话内取得独占运行时锁后才允许启动内核或修改系统代理。第二个应用实例 SHALL 激活已有窗口或报告已有实例，而不得启动第二个内核、覆盖运行时记录或修改系统代理。

#### Scenario: 第二个实例启动

- **WHEN** 同一 Windows 用户会话中已有实例持有运行时锁
- **THEN** 新实例不启动受管内核且不修改系统代理，并将焦点交给已有实例或返回已有实例状态

### Requirement: 本地控制接口保护

系统 MUST 将 sing-box 的管理和活跃连接接口限制为本机回环地址，并为每次内核运行生成独立的高熵认证密钥。认证密钥与临时配置 MUST 仅允许当前用户读取，且不得出现在日志、快照、导出内容或错误摘要中；运行时结束后 MUST 删除临时配置和密钥。

#### Scenario: 外部地址尝试访问控制接口

- **WHEN** 非回环地址尝试连接 sing-box 管理或活跃连接接口
- **THEN** 接口不监听该地址且不会返回运行时或连接数据

### Requirement: 受管内核生命周期

系统 MUST 为每次受管内核运行记录进程身份、配置修订和启动时间，并在退出、替换或故障后停止属于该运行时的进程。系统 SHALL 在内核意外退出时更新快照并保留足以诊断的错误摘要。

#### Scenario: 应用退出时清理运行时

- **WHEN** 用户退出应用或运行时被显式停止
- **THEN** 系统停止受管内核、恢复本应用管理的系统代理设置并清除活跃运行时标识

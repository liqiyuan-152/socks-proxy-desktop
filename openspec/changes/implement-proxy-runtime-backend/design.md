## Context

当前 `src-tauri/src/lib.rs` 只有托盘初始化和内存中的 `ProxyMode`，没有 Tauri 命令、配置存储或任何代理内核。`src/` 的代理、规则、状态、日志和设置页面均使用静态数组或 React 会话状态。详见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 建立可独立测试的 Rust 领域层，前端仅通过稳定的 IPC DTO 读写状态。
- 让“已应用模式”成为内核、系统代理和持久化配置都成功后的提交结果。
- 保证密码、系统代理原始值和诊断数据有明确的所有权与脱敏边界。
- 以 Windows 为首个受支持平台，但将平台操作隔离在适配器边界后。

**Non-Goals:**

- 不自行实现 SOCKS、HTTP、TUN 或 DNS 转发协议栈。
- 不承诺未验证的全流量接管、TUN、DNS 接管、跨平台系统代理实现或远程订阅。
- 不将前端现有的示例档案、连接统计或健康文本迁移为真实数据。

## Decisions

### 1. 将代理执行委托给受管的 sing-box 进程

应用生成经过校验的 sing-box JSON 临时配置、启动随应用打包的 sing-box 二进制，并用可验证监听端口、进程退出和活跃连接快照驱动状态机。首期锁定 `sing-box v1.14.1`：从 `SagerNet/sing-box` GitHub Release 获取 `sing-box-1.14.1-windows-amd64.zip`，打包前校验 ZIP 的 SHA-256 `5197f16d492d93202dc623622149a6ed040f8eca263128f91d603f2b901baa89`；启动前校验包内 `sing-box.exe` 的 SHA-256 `b838de45bd0b2e6ddbed1977e4745622f7dffab3b293807ff4c6b1b640fed909`。两者不可混用，并将发布提交 `1ac1a339cb1223e9c70eae14c44411c75033c02d` 的有效 PGP 验证记录纳入发布清单。该核心采用 GPLv3，发布和分发必须履行其许可义务。任务 1.1 的硬性门槛是验证其 Clash API 的 `127.0.0.1` 回环绑定、每次运行独立 Bearer secret，以及活跃连接中的目标、规则和出口链字段；验证失败时该变更不得进入实现阶段。sing-box 负责 SOCKS/HTTP 上游、规则匹配和可选 TUN；Tauri 后端只负责生命周期、配置和平台集成。

固定版本验证使用上述发布提交在 macOS arm64 上以 `with_clash_api` 构建，并使用 `src-tauri/tests/fixtures/sing-box-v1.14.1-observability.json` 运行。`GET /connections` 在缺少 `Authorization: Bearer <secret>` 时返回 `401`；在 `127.0.0.1` 上带 token 可返回快照，而本机非回环地址无法连接。字段映射为：`connections[].metadata.host` 和 `destinationPort` 映射目标，`connections[].rule` 映射命中规则，`connections[].chains` 映射出口链。该接口不返回完成结果、失败原因或历史记录；这些字段在首期 DTO 中必须为不可用，而非空值代表成功。

选择 sing-box 而非 mihomo 是因为首期重点是结构化的 SOCKS/HTTP 档案、规则和运行时状态，而非 Clash 订阅或代理组兼容。备选方案是直接用 Rust 实现转发和规则引擎；它会把协议兼容性、DNS、UDP、TUN 和安全维护扩大到应用内，不适合当前从零开始的后端。

### 2. 使用领域状态机和单一串行编排器

`RuntimeCoordinator` 持有 `Stopped`、`Starting`、`Running`、`Switching`、`Recovering`、`Failed` 等内部阶段及最后一个已提交运行时。每个 Windows 用户会话先获取独占运行时锁，所有启动、停止、档案选择、活动档案更新、规则更新、导入和模式切换再经同一异步队列执行。候选配置成功启动或重载、健康检查及系统代理操作全部完成后才替换 `applied_mode` 并持久化候选修订；否则恢复最后一次提交的运行时与配置修订。

这比让托盘回调和多个 Tauri 命令各自修改状态可靠。代价是切换请求排队，前端必须禁用重复提交并展示后端阶段。

### 3. 配置、凭据与运行时数据分层

非敏感配置保存为带 schema version 的本地 JSON 或 SQLite 数据；密码使用操作系统凭据存储，并以稳定档案 ID 作为引用。凭据更新 DTO 使用显式的保留、替换和删除意图，禁止以空字符串推断。设置模型包含开机启动和日志保留策略；默认保留 30 天，永久模式仍受 100,000 条运行时诊断记录上限约束。运行时配置、控制接口密钥和临时内核文件创建于应用数据目录的当前用户受限位置，停止后删除。Clash API 的 `/connections` 仅提供脱敏的活跃连接快照，不提供完成结果或失败字段；因此首期不持久化连接历史、不计算成功/失败日聚合，也不从 `/logs` 的非结构化文本推断连接结果。连接列表和状态统计在接口不可用时报告观测降级；运行时诊断独立保存并受保留策略控制。导入在独立解析和校验、并完成运行时候选提交后原子替换非敏感配置，导出与复制详情均使用展示 DTO。

备选方案是将全部配置加密后放入单一文件。其密钥管理仍要依赖系统凭据，且导入导出和故障恢复更难审计。

### 4. 系统代理采用带恢复记录的 Windows 适配器

`SystemProxyAdapter` 在写入前读取并持久化原始 Windows 代理设置、本应用写入后的预期设置和所有权令牌。写入前先持久化待写入状态；完成后再标记提交。恢复时若当前完整设置等于已提交的预期值，才可恢复原值；若写入中断且当前完整设置仍等于原值，可安全清理待写记录；若当前设置等于已记录的待写入预期值，可恢复原值。当前设置既不等于原值也不等于已记录的预期值时，无法区分部分写入与第三方修改：不得猜测字段归属或自动覆盖，须保留现场和恢复记录，报告需人工检查的错误，并阻止新的系统代理接管。启动恢复先于新内核启动；用户触发的网络恢复也遵循同一判断。适配器返回结构化结果而非直接更新 UI 文本。

备选方案是由前端调用 shell 或直接编辑注册表；这会绕过错误处理、所有权检查和可测试边界。未启用 TUN 时，系统代理只影响遵循 Windows 用户级系统代理设置的应用；快照和 UI 必须明确这一范围。TUN 状态独立于系统代理状态，只有内核明确报告启用后才为真。

### 5. IPC 以版本化 DTO 和事件推送为边界

Tauri 命令按配置、运行时、设置和日志分组，返回不含秘密的 DTO 与统一错误码。配置命令覆盖档案与规则的列表、增删改、选择和排序；设置命令覆盖开机启动、保留策略、导入导出和网络恢复；日志命令覆盖筛选分页、详情和确认后清理。后端在状态转换后发出 `runtime://snapshot` 事件；前端初始加载调用快照命令，并将事件作为状态页、侧栏、底栏和托盘的唯一更新源。命令不接受前端传入的“已应用状态”。

自动更新没有已配置的发布渠道、签名或更新器，因此首期不提供检查更新命令；前端必须将该入口显示为不可用或明确说明未配置，而不是发起伪请求。

## Risks / Trade-offs

- [sing-box 二进制的许可证、签名、版本与架构不匹配] → 在打包前建立清单、版本探测和启动前校验；缺失或不兼容时拒绝启动并给出明确错误。
- [Windows 系统代理写入失败或异常退出遗留设置] → 写入前持久化原值及待写预期值，启动时按完整设置匹配可确认的状态后恢复；逐字段写入留下无法确认归属的中间状态时保留现场及记录、阻止新接管并提示人工检查；所有恢复结果写入诊断日志。
- [凭据进入导出、日志或 IPC] → 用类型分隔带密 DTO 与展示 DTO，并为序列化、导出和日志增加负向测试。
- [sing-box 活跃连接接口或字段映射变化] → 任务 1.1 锁定接口契约并用固定版本集成测试验证；验证失败阻塞本变更，不进入实现阶段。`/connections` 不含完成结果或失败字段，因此首期将历史连接观测明确报告为不可用，禁止推断。
- [第二实例或外部应用覆盖系统代理] → 每用户会话独占运行时锁；恢复前比较预期设置，不匹配时保留外部设置并提示用户。
- [本地控制接口被非预期访问] → 仅绑定回环地址、每次运行生成高熵密钥、限制临时配置 ACL，并在退出时删除密钥与配置。
- [模式切换期间流量短暂中断] → 串行切换、保持最后已提交状态、在 UI 显示切换中并记录可观测的切换结果。

## Migration Plan

1. 先锁定 sing-box 二进制和活跃连接接口契约，再引入配置模式、存储迁移与只读命令，保持前端静态页面不变。
2. 将前端逐页改为读取配置、设置、日志和运行时 DTO；未启用 TUN 时明确显示系统代理覆盖范围，未实现操作显示真实的不可用状态而非示例成功数据。
3. 接入内核和 Windows 系统代理适配器，先在开发环境使用显式测试档案验证启动、切换、回滚和退出恢复。
4. 打包内核二进制与恢复机制后，启用正式模式切换；若运行时初始化失败，保留前端可编辑配置并恢复系统代理，不保留半应用状态。
5. 后续启用 TUN 时，新增独立 OpenSpec 变更来定义提权、DNS、驱动兼容性和全流量接管行为。

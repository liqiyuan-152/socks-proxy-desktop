## Why

当前桌面应用的代理、规则、状态、连接日志和设置全部是前端会话内的静态数据；Rust 后端仅维护托盘菜单的勾选状态。因此用户切换模式、编辑代理或关闭应用后，既不会改变实际网络路径，也无法获知运行时是否健康。需要先建立可持久化、可观察且可恢复的代理后端，才能让现有界面反映真实事实。

## What Changes

- 新增代理配置存储：持久化代理档案、分流规则、活动档案和应用设置；对输入做协议、主机、端口与规则校验，并将密码与普通配置分离保存。
- 补齐设置页后端：持久化开机启动和日志保留策略，支持不含凭据的配置导入导出、受控日志清理和网络恢复；未配置更新服务时明确返回不可用，不伪装为已检查更新。
- 新增代理核心编排：以受管的 sing-box 内核进程提供本地监听、规则代理、全局代理和全局直连三种模式；首期规则与全局模式只覆盖遵循 Windows 系统代理设置的流量，将模式切换设计为串行事务，失败时恢复上一个已应用状态。
- 新增 Windows 系统代理适配器：仅在运行时已经就绪后写入应用拥有的系统代理设置；停止、切换直连、启动失败或退出时恢复启动前的设置。
- 新增前后端控制面：以强类型 Tauri 命令和事件提供配置读写、模式切换、运行时快照、最近连接和日志查询；状态页、侧栏、底栏和托盘不得各自维护或展示互相矛盾的本地状态。
- 新增可观测性与恢复：通过已验证的本地接口展示脱敏的活跃连接快照，并记录运行时诊断、运行时长、内核状态和失败原因；首期不将内核文本日志推断为已完成连接、成功率或失败历史。退出时清理受管进程和系统代理，下一次启动时检测并恢复异常遗留状态。
- 不在首期承诺全局 TUN 接管、DNS 劫持、自动更新或任意平台代理驱动。只有内核实际启用并验证 TUN 后，状态接口才允许报告 TUN 已启用。

## Capabilities

### New Capabilities

- `proxy-configuration`: 管理并安全持久化代理档案、分流规则、活动选择和应用设置。
- `proxy-runtime`: 编排代理内核、模式切换和 Windows 系统代理恢复，并向前端公开真实运行时状态。
- `proxy-observability`: 提供脱敏活跃连接快照、观测降级状态和可诊断的运行时日志。

### Modified Capabilities

- 无。仓库尚无已发布的 OpenSpec 功能规格。

## Impact

- Rust：`src-tauri/src/` 将从单一托盘初始化拆分为领域模型、存储、内核进程管理、系统代理适配、Tauri 命令和事件模块；新增 Tokio、配置存储、凭据存储和日志所需依赖。
- 前端：`src/` 将用 Tauri IPC 数据源替换静态数组与会话状态，并在切换期间展示后端返回的实际阶段和失败信息。
- 平台：首期以 Windows 系统代理为受支持目标；sing-box 二进制的打包、版本校验和权限需求须在实现前明确。
- 安全：密码不得写入普通配置文件、应用日志、Tauri 事件或连接记录；导入导出必须排除凭据或要求用户重新输入。
